# ApplicationContext의 추가 기능

이 장의 소개에서 설명한 것처럼, `org.springframework.beans.factory` 패키지는 프로그래밍 방식을 포함하여 빈을 관리하고 조작하기 위한 기본 기능을 제공한다. `org.springframework.context` 패키지는 애플리케이션 프레임워크 지향적인 스타일로 추가 기능을 제공하기 위해 다른 인터페이스를 확장할 뿐만 아니라 `BeanFactory` 인터페이스를 확장하는 [`ApplicationContext`](https://docs.spring.io/spring-framework/docs/6.1.11/javadoc-api/org/springframework/context/ApplicationContext.html) 인터페이스를 추가한다. 많은 사람들이 `ApplicationContext`를 완전히 선언적인 방식으로 사용하며, 프로그래밍 방식으로 생성하지 않고 `ContextLoader`와 같은 지원 클래스에 의존하여 자카르타 EE 웹 애플리케이션의 일반적인 시작 과정의 일부로 `ApplicationContext`를 자동으로 인스턴스화한다.

보다 프레임워크 지향적인 스타일로 `BeanFactory` 기능을 향상시키기 위해 컨텍스트 패키지는 다음과 같은 기능도 제공한다.

- `MessageSource` 인터페이스를 통해 i18n 스타일의 메시지에 액세스한다.
- `ResourceLoader` 인터페이스를 통해 URL 및 파일과 같은 리소스에 액세스할 수 있다.
- 이벤트 퍼블리싱, 즉 `ApplicationListener` 인터페이스를 구현하는 빈에 `ApplicationEventPublisher` 인터페이스를 사용하여 퍼블리싱할 수 있다.
- 여러 (계층적) 컨텍스트를 로드하여 각각 애플리케이션의 웹 레이어와 같은 특정 레이어에 집중할 수 있도록 `HierarchicalBeanFactory` 인터페이스를 통해 설정할 수 있다.

##   `MessageSource`를 사용한 국제화

`ApplicationContext` 인터페이스는 `MessageSource`라는 인터페이스를 확장하므로 국제화("i18n") 기능을 제공한다. 또한 스프링은 메시지를 계층적으로 해결할 수 있는 `HierarchicalMessageSource` 인터페이스도 제공한다. 이러한 인터페이스는 함께 스프링이 메시지 해결에 영향을 미치는 기반을 제공한다. 이러한 인터페이스에 정의된 메서드는 다음과 같다.

- `String getMessage(String code, Object[] args, String default, Locale loc)`: `MessageSource`에서 메시지를 검색하는 데 사용되는 기본 메서드. 지정된 로캘에 대한 메시지를 찾을 수 없으면 기본 메시지가 사용된다. 전달된 모든 인수는 표준 라이브러리에서 제공하는 `MessageFormat` 기능을 사용하여 대체 값이 된다.
- `String getMessage(String code, Object[] args, Locale loc)`: 본질적으로 이전 메서드와 동일하지만 한 가지 차이점이 있다. 기본 메시지를 지정할 수 없다. 메시지를 찾을 수 없으면 `NoSuchMessageException`이 발생한다.
- `String getMessage(MessageSourceResolvable resolvable, Locale locale)`: 앞의 메서드에서 사용된 모든 속성은 이 메서드와 함께 사용할 수 있는 `MessageSourceResolvable`이라는 클래스로 래핑된다.
